## Детали

### 🔴 1. Секреты в `config.toml`, закоммиченном в git
- **Где:** `config.toml` отслеживается git (`git ls-files`), `.gitignore` его НЕ игнорирует.
- **Что в нём:** `tg_token`, `tg_chat_id`, `vk_token`, `vk_user_id`, `proxy_string` (с логином/паролем),
  `proxy_change_url`, `cookies_api_key`.
- **Риск:** при заполнении секретов и `git commit` они утекут в историю (и в публичный форк/PR).
  Даже после удаления останутся в истории git.
- **Рекомендация:** вынести секреты в `.env`/переменные окружения или отдельный приватный файл вне git.
  Добавить `config.toml` (или хотя бы секретные поля) в `.gitignore`, хранить `config.example.toml`.
  Подробности и готовое решение — в `SECRETS_MANAGEMENT.md`.

### 🟠 2. Скудный `.gitignore`
- Игнорируется только `.secret.txt`. **Не игнорируются** `database.db`, `result/`, `logs/`,
  `storage/`, `__pycache__/`, `config.toml`, `.env`.
- **Риск:** случайный коммит БД, логов (могут содержать чувствительные данные), cookies, секретов.
- **Рекомендация:** расширить `.gitignore` (P1).

### 🟠 3. Контейнер от root
- В `Dockerfile` нет `USER`. Процесс и любые RCE-последствия — с правами root внутри контейнера.
- **Рекомендация:** добавить непривилегированного пользователя; `cap_drop: [ALL]`, `security_opt: no-new-privileges`.

### 🟡 4. Telegram token в URL
- `integrations/notifications/telegram.py`: токен в пути `…/bot{token}/sendMessage`.
- Это стандарт Telegram API, но **токен может попасть в логи** при логировании URL/исключений.
  Сейчас прямого логирования URL нет, но `send_with_retries` логирует объект исключения `e`
  (`requests.HTTPError`), который **может** содержать URL с токеном.
- **Рекомендация:** убедиться, что токен не утекает в логи; при необходимости маскировать.

### 🟠 5. Нет сканирования зависимостей
- Нет `pip-audit`/Dependabot/Trivy/CodeQL. `curl_cffi`/`httpx` без пина версий.
- **Рекомендация:** добавить `pip-audit` в CI и Trivy для образа (P1).

### 🟡 6. SSRF / неконтролируемые URL
- `MobileProxy.handle_block` (`proxy.py`) и `PlaywrightClient.change_ip` (`get_cookies.py`) делают
  GET на `change_ip_link`/`proxy_change_url` из конфига. URL задаёт владелец конфига → доверенный ввод,
  но это сетевые запросы по произвольному URL.
- `urls` из конфига → запросы к Avito; домен не валидируется (можно указать любой сайт).
- **Риск:** низкий в однопользовательском сценарии (конфиг = владелец). **Станет важным** в
  мультиарендной/сервисной версии (пользователь сможет задать внутренний URL) → нужна валидация (allowlist `avito.ru`).

### 🟢 7. Excel formula injection — уже закрыто
- `parser/export/excel.py: excel_safe()` экранирует значения, начинающиеся с `= + - @`. ✅

### 🟢 8. Telegram MarkdownV2 — в целом корректно
- `integrations/notifications/utils.py: escape_markdown_v2()` экранирует спецсимволы. Заголовки/цены/продавец проходят экранирование. Риск инъекции разметки низкий.

### 🟢 9. Десериализация / shell / command injection
- `subprocess.run` только в `playwright_setup.py` с фиксированным списком аргументов (без `shell=True`) — ок.
- Нет `pickle`/`eval`/`exec` на недоверенных данных. JSON парсится штатно. ✅

### 🟡 10. Хранение cookies / доступ к файлам
- `utils/prompt_user_login.py` ставит `chmod 0o600` на `own_cookies.json` — ✅ хорошо.
- `external_api`/`own_cookies` пишут в `storage/` без явного chmod — наследуют umask.
- **Рекомендация:** ограничить права каталога `storage/` (0700) на сервере.

### 🟡 11. Публичные порты
- Приложение **не открывает сетевых портов** (нет сервера). Атакуемая поверхность по входящим — нулевая.
  Это плюс для безопасности. (Появится при добавлении REST API/веб-панели — тогда нужен reverse-proxy + auth.)

## Рекомендации (приоритеты)
1. **P0:** вынести секреты из git/`config.toml` → `.env`/секреты; расширить `.gitignore`.
2. **P1:** non-root в Docker, `cap_drop`, `no-new-privileges`; `pip-audit`/Trivy в CI; пин версий.
3. **P1:** не допускать утечки токенов в логи (проверить `send_with_retries`).
4. **P2 (для сервиса):** валидация/allowlist URL (anti-SSRF), права на `storage/`.
5. **Юридическое:** добавить LICENSE (или согласовать условия использования с автором upstream).
