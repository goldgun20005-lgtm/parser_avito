# FINAL_REPORT — Итоговый отчёт

> Статус: **Предварительный (Фаза A завершена).** Разделы про выбранную архитектуру, сервер,

## 1. Что представляет собой проект
Настольное/серверное Python-приложение (GUI на Flet + CLI) для мониторинга новых объявлений
Avito.ru по заданным ссылкам с уведомлениями в Telegram/VK и экспортом в Excel. Версия **3.2.15**
(2026-06-15). Подробно — `REPOSITORY_OVERVIEW.md`, `HOW_IT_WORKS.md`.

## 2. Подходит ли он под мою задачу
_Ожидается_ — после ответов. Предварительно: для личного мониторинга нескольких/десятков ссылок —
**да, подходит** (с прокси/spfa). Для коммерческого мультипользовательского сервиса — требует
существенной переработки (`DEPLOYMENT_OPTIONS.md` Вариант 3).

## 3. Работает ли текущая версия
- **Подтверждено кодом:** архитектура целостная, синтаксис корректен (Python 3.11).
- **Подтверждено локальным smoke-тестом (12 тестов):** импорт всего проекта, фабрика нотификаторов,
  доставка webhook (+source+secret), дедуп `(id,price)`, миграция БД, ENV-секреты, tolerant-парсинг,
  backoff, атомарная запись Excel.
- **Не проверено (egress песочницы блокирует avito.ru):** реальный парсинг страниц Avito и доставка
  в боевой n8n — выполнять на сервере (Уровни 4–5 `TEST_REPORT.md`).
- **Риск #306/#307 снижен:** битое объявление больше не роняет страницу (tolerant-парсинг).

## 4. Что было проверено
Структура, точки входа, бизнес-логика, модели, БД, фильтры, уведомления, экспорт, cookies/proxy,
Docker/compose/entrypoint, CI, зависимости, Issues upstream (39 открытых), статический Уровень 1.

## 5. Что не удалось проверить
Реальные запросы к Avito, дедупликация в рантайме, доставка уведомлений, Docker-сборка/запуск,
длительная работа 6–24 ч (требуют установки зависимостей/сети — Фаза C/D).
