# DEPLOYMENT_PLAN — План развёртывания

> Статус: **Ожидаются ответы пользователя и выбор варианта** (`DEPLOYMENT_OPTIONS.md`).
> Этот план будет конкретизирован под вашу инфраструктуру (ОС, ресурсы, прокси, каналы уведомлений).
> Ничего на сервере не устанавливается до согласования. Ниже — каркас по структуре §19 промта.

## 19.1. Подготовка сервера (каркас)
- обновление системы; создание непривилегированного пользователя; SSH (ключи); firewall;
  fail2ban (при необходимости); синхронизация времени + часовой пояс; Docker + Compose; Git;
  каталоги проекта (`/opt/parser_avito/{config,data,result,storage,logs,backups}`); права доступа.

## 19.2. Подготовка проекта (каркас)
- fork/clone; выбор версии (commit/tag, по умолчанию текущий `c6e373c` = 3.2.15); проверка commit;
  рабочая ветка; копирование `config.example.toml` → `config.toml`; создание `database.db`
  (`touch`) и каталогов данных; настройка секретов (`.env`/на сервере, см. `SECRETS_MANAGEMENT.md`).

## 19.3. Настройка приложения (каркас)
- URL(ы), `count` (стр.), интервалы (`pause_general`/`pause_between_links`), фильтры,
  Telegram/VK, экспорт (`save_xlsx`), cookies (own/spfa), прокси, `retry_delay`/`timeout`/
  `max_count_of_retry`/`block_threshold`, лимиты.

## 19.4. Первый запуск (каркас)
- сборка образа (локально, не `latest`); старт; просмотр логов; проверка версии в логе;
  тест запроса; тест сохранения (Excel/БД); тест уведомления; повторный запуск; проверка дедупликации.

## 19.5. Production-запуск (каркас)
- `restart: unless-stopped`; healthcheck; лимиты CPU/RAM; ротация логов; backup (cron);
  мониторинг (Uptime Kuma + Telegram-alert); план обновления (`UPDATE_AND_ROLLBACK.md`).

## 19.6. Проверка после установки (каркас чек-листа)
| Шаг | Команда | Ожидаемый результат |
|---|---|---|
| Контейнер запущен | `docker ps` | статус `Up` |
| Версия | `docker compose logs | grep "Запуск AvitoParse"` | `v3.2.15` |
| Парсинг | `docker compose logs --tail=50` | строки `Объявлений перед чисткой N`, `После фильтрации …` |
| Дедуп | повторный проход | нет повторных уведомлений |
| Persistence | `docker compose restart` | `database.db`/`result` на месте |
| Backup | `./scripts/backup.sh` | копия БД + `integrity_check` ok |

> Полный пошаговый план с конкретными командами будет готов после выбора варианта и получения данных сервера.
