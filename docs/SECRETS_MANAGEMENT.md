# SECRETS_MANAGEMENT — Управление секретами

> Статус: технический раздел готов; финальный выбор зависит от масштаба (см. опросник).
> Проблема (см. `SECURITY_AUDIT.md`): сейчас секреты лежат в `config.toml`, который **отслеживается git**.

## Какие данные считаются секретами
- `tg_token` (Telegram Bot Token), `tg_chat_id` (если приватный)
- `vk_token`, `vk_user_id`
- `cookies_api_key` (spfa.ru)
- `proxy_string` (логин:пароль@host:port), `proxy_change_url`, `proxy_notifier`
- cookies-файлы (`storage/*.json`), SSH-ключи, IP с учётными данными

## Варианты хранения (по возрастанию строгости)

| Вариант | Когда подходит | Плюсы | Минусы |
|---|---|---|---|
| `.env` (+ docker-compose `env_file`) | личное/надёжное использование | просто, стандартно, вне git | переменные видны в `docker inspect` |
| Отдельный приватный `config.toml` вне git | минимальный вариант | минимум правок кода | легко случайно закоммитить |
| Docker secrets / mounted secrets | swarm/совместимые оркестраторы | не попадают в ENV/inspect | сложнее настройка |
| Vault / SOPS / age | сервис, команда | ротация, аудит | оверкилл для одиночного парсера |

## Рекомендация по масштабу
- **Личное / один сервер:** `.env` + `config.toml` без секретов (секреты подставляются из ENV) **или**
  приватный `config.toml`, исключённый из git. Файлы `0600`, каталог `storage/` `0700`.
- **Надёжная эксплуатация:** `.env` через `env_file` в compose + строгий `.gitignore` + бэкап секретов отдельно от репо.
- **Сервис/мультиарендность:** секретница (Vault/Doppler) или секреты оркестратора.

## Минимальный безопасный набор изменений (кандидаты, в аудите НЕ применены)
1. Добавить в `.gitignore`:
   ```
   .env
   config.toml
   storage/
   database.db
   result/
   logs/
   __pycache__/
   *.bak
   ```
   > Если `config.toml` нужен в репо как пример — хранить `config.example.toml`, а рабочий `config.toml` игнорировать.
2. Убрать секреты из текущего `config.toml` (оставить пустые строки) и удалить их из истории git
   (`git filter-repo`/BFG) **если** туда уже попадали реальные значения.
3. (Опц.) Доработать `load_config.py`, чтобы секреты можно было переопределять из ENV
   (напр. `AVITO_TG_TOKEN`, `AVITO_VK_TOKEN`, `AVITO_COOKIES_API_KEY`, `AVITO_PROXY_STRING`).
   Это правка кода уровня P0.3 из `IMPROVEMENT_ROADMAP.md`.

## Что отдаётся в чат, а что нет
- В чат: **только** какие каналы используете и общие параметры. **Никаких** реальных токенов/паролей/ключей.
- Реальные значения вносим прямо на сервере в `.env`/`config.toml` или через переменные окружения.

## Файлы-примеры (созданы в репозитории, без реальных секретов)
- `config.example.toml` — шаблон конфигурации с комментариями.
- `.env.example` — шаблон переменных окружения для docker-compose.
